# Integrated open-source research worker

Source inspection date: 2026-10-19, America/Denver. This note describes inspected source and the implemented coordinator; installation, an import smoke test, a real provider run, and production operation are distinct checks.

## Decision

One TIKYTOKY research job coordinates collection, media evidence, optional public-page enrichment, and a GPT Researcher investigation. The user does not operate separate research applications. The main worker calls `worker/tikytoky/web_research.py:investigate(request, videos, emit)` and receives one `{report, sources, warnings, engine}` result.

GPT Researcher is actually instantiated and its `conduct_research()` and `write_report()` methods run. It plans subquestions and produces a report over the collected corpus. It does not become an unsupported label on a direct LLM prompt. SearxNG can discover supporting URLs; Crawl4AI extracts readable text; collected video transcripts, visual notes, and real metric snapshots remain traceable evidence. This report supplies creative research, while the user's knowledge documents remain the factual source for generated scripts.

The browser automation runtime and research runtime are separate virtual environments behind that single coordinator. A resolved dependency conflict requires this: `browser-use==0.13.11` requires `mcp==2.1.1`; `gpt-researcher==0.16.1` requires `mcp>=1.9.1,<2.0.0`. Overriding either constraint would not be an intact upstream integration. Python 3.12 is available locally and supports both environments. No older GPT Researcher substitute is used.

## Genuine GPT Researcher integration

The supported constructor accepts `documents`, `source_urls`, `config_path`, `role`, and `context`. `LangChainDocumentLoader` converts each `Document.page_content` into `raw_content` and uses `metadata['title']` as its citation URL; the coordinator sets that field to the exact collected source URL. [Constructor](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/agent.py#L53-L83), [document adapter](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/document/langchain_document.py#L10-L24).

Using `source_urls` would cause GPT Researcher to scrape those URLs itself. That would unnecessarily repeat browser collection and make the observed corpus harder to bound. Instead, `report_source='langchain_documents'` supplies the already collected evidence. GPT Researcher's current planning flow still calls its retriever for initial results, even with supplied documents. The coordinator therefore uses the supported custom retriever, which returns only the same collected corpus from an ephemeral loopback HTTP endpoint. Subqueries select relevant source records; they cannot ask that endpoint to fetch arbitrary new pages. [Source/document behavior](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/skills/researcher.py#L143-L207), [initial search and subquestion planning](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/skills/researcher.py#L364-L400), [custom retriever contract](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/retrievers/custom/custom.py#L8-L24).

OpenRouter is a native provider. Its implementation uses `OPENROUTER_API_KEY` and the official OpenRouter API base through ChatOpenAI. The coordinator sets FAST/SMART/STRATEGIC LLMs to `openrouter:<OPENROUTER_MODEL>`, disables generated images and MCP tools, caps iterations, and selects `CONTEXT_FILTER='none'` so this bounded evidence stage does not require a separate embedding provider. Operator settings are restored after the stage. [Native OpenRouter implementation](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/llm_provider/generic/base.py#L280-L298), [filter/config defaults](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/config/variables/default.py#L3-L18), [config precedence](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/config/config.py#L54-L80).

The main process invokes the isolated interpreter with a JSON stdin request. Provider keys are inherited through the environment and never put in command arguments. Third-party stdout is redirected to stderr inside the research process; the parent discards those logs and parses one bounded JSON stdout response. Missing runtime, missing credentials, timeouts, dependency errors, or an unexpected citation URL return a blocked/failed engine state and no fabricated report.

## Crawl4AI's role and public-only limits

`AsyncWebCrawler` with `BrowserConfig` and `CrawlerRunConfig` is the supported async API. The worker calls `arun` for at most five selected public pages. It enables `check_robots_txt`, disables JavaScript and stealth, limits page time, rejects local/private/credential URLs, checks DNS answers, and aborts nonpublic browser requests and media/font resources. It does not authenticate, solve CAPTCHAs, bypass paywalls, or turn access-denied pages into evidence. [Async API](https://github.com/unclecode/crawl4ai/blob/94b67888ca8b335ff2121423a50e06dd27661922/crawl4ai/async_webcrawler.py#L216-L252), [robots enforcement](https://github.com/unclecode/crawl4ai/blob/94b67888ca8b335ff2121423a50e06dd27661922/crawl4ai/async_webcrawler.py#L389-L405), [browser options](https://github.com/unclecode/crawl4ai/blob/94b67888ca8b335ff2121423a50e06dd27661922/crawl4ai/async_configs.py#L1068-L1086).

These application checks reduce accidental internal access. Strong protection against DNS rebinding and arbitrary browser egress requires a network-level egress policy for the worker runtime; URL checks alone are not that guarantee. Crawling uses static readable text, so JavaScript-only pages can fail and are reported as unavailable. Public page text remains untrusted evidence and cannot issue agent instructions.

## Optional self-hosted SearxNG

The documented API accepts GET `/search?q=...&format=json` or equivalent form POST. JSON must be enabled in `settings.yml`; an unenabled format returns HTTP 403. Many public instances intentionally disable machine-readable formats, and upstream's default settings enable only HTML. TIKYTOKY does not scan public instances or silently switch to one. [Search API and 403 behavior](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/docs/dev/search_api.rst#L7-L35), [HTML-only defaults](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/searx/settings.yml#L82-L87).

An operator-managed instance can be reached through `SEARXNG_URL`, normally `http://127.0.0.1:8080` from the same host or `http://searxng:8080` from an explicitly configured compose network. Enable `search.formats: [html, json]` and keep its listener private to the worker. The official container runs on internal port 8080 and persists settings under `/etc/searxng`; use Docker Desktop with its WSL2 backend on this Windows workstation or an existing Linux Docker host. Installing or altering Docker/WSL is a separate machine setup step, not something a source audit proves happened. [Official container instructions](https://docs.searxng.org/admin/installation-docker.html), [pinned container instructions](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/docs/admin/installation-docker.rst#L187-L195).

`time_range` supports only day/month/year and only engines with time filtering. A seven-day request therefore uses a broader month search for supporting research; the video's exact publication-window filtering remains the video collection stage's responsibility. Search coverage is a sample and supporting pages supply no invented video metrics. [API time-range limits](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/docs/dev/search_api.rst#L64-L72).

## License/attribution handling

- Keep GPT Researcher's actual distributed Apache LICENSE alongside the unresolved MIT metadata note; do not claim a cleaned-up upstream license resolution.
- Crawl4AI's LICENSE adds an explicit credit requirement. Include its prescribed credit in the application's Credits/About and distribution documentation: software by UncleCode as part of Crawl4AI. Preserve the upstream text in third-party notices. [Attribution clause](https://github.com/unclecode/crawl4ai/blob/94b67888ca8b335ff2121423a50e06dd27661922/LICENSE#L54-L67).
- SearxNG remains a separate unmodified AGPL service. Preserve its license/source attribution when distributing the service, and evaluate AGPL obligations before modifying it or distributing a changed service. HTTP interoperability does not remove upstream obligations.

## Verification so far

Thirteen coordinator tests passed under local Python 3.12, without external network or paid provider calls. They cover public-source rejection, private DNS answers, missing evidence labels, corpus bounds, deterministic source selection, environment restoration, known/unknown citation URLs and absent citations, missing dependencies/keys, unavailable search, and a missing isolated runtime. The Windows sandbox blocked asyncio's socket support; the same tests passed with ordinary host socket access. Unit tests with mocked synthesis do not establish a successful real GPT Researcher/provider run. Record that separately after dependency installation.

## Installed live verification — October 20, 2026

The isolated GPT Researcher 0.16.1/Crawl4AI 0.9.5 environment installed and imported successfully. A real Crawl4AI request extracted the official Browser Use repository page; actual GPT Researcher planning and writing completed a 1,798-character report with the supplied GitHub source citation and explicit missing-evidence limits. The output was software-documentation analysis, not viral-video findings.
