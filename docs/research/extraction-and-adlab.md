## AdLab: a useful analysis specification, not a standalone app

The repository contains markdown instructions, a teardown framework, two small plugin metadata files, and a future plan. It has no Python/JavaScript analysis engine, API server, storage layer, search client, dependency lockfile, tests, or frontend. The actual extraction engine is a separate repository, `bradautomates/claude-video`, expected to exist as the `watch` skill. This dependency is declared rather than vendored or pinned. [Dependency discovery and preflight](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/SKILL.md#L20-L48), [repository tree](https://github.com/Splitwolf1/adlab/tree/59f792a5546c00b0a377ea550e065e9ea26e696e).

Its extraction specification runs the external `watch.py` twice: a hook pass over seconds 0–3 at 2 fps and 1024-pixel resolution, then a full-video pass. A host agent is instructed to inspect the extracted frames and align them to a transcript. These instructions are not executable implementations inside AdLab. [Extraction and evidence review](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/SKILL.md#L57-L80).

The useful intellectual contribution is a rubric: scroll-stop, visual/audio/text hook, payoff near second three, dominant modality, editing rhythm, open loops, emotion, message structure, CTA, and production format. Scores are subjective 1–5 judgments tied to timestamps. Its visual/audio percentage split is explicitly an estimate, not measured retention. [Rubric](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/reference/teardown-framework.md#L3-L66).

Generation is another host-agent instruction. It abstracts 4–7 rules, adapts the mechanism to a named app, and asks the agent to emit prompts for external marketing/video tools. It has no independent LLM client or generated-script schema and supplies no reproducibility or quality validation. [Recipe and adaptation specification](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/reference/teardown-framework.md#L114-L137), [handoff instructions](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/SKILL.md#L82-L108).

The batch research loop is only a proposal: scrape creator accounts, divide views by creator median views, select outliers, analyze them, save a playbook, and adapt patterns. The final section explicitly says this is not built. The plan's historical prices and its causal explanation for outliers are author claims, not verified facts or proof of what drives reach. [Future plan and formula](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/PLAN-tiktok-intel.md#L16-L32), [unimplemented status](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/PLAN-tiktok-intel.md#L55-L57).

### Dependencies and license

- Runtime instructions require external `watch`, Python, yt-dlp, FFmpeg, and optional Groq/OpenAI Whisper credentials. AdLab does not pin versions or include these implementations. [Requirements](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/README.md#L39-L64).
- MIT is declared in skill front matter and Claude plugin metadata, but no standalone LICENSE/copyright notice exists in the pinned tree. Prefer original implementation of the architectural ideas; preserve notices if reusing any source text. This audit does not establish rights in external watch/video-generation dependencies. [Skill declaration](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/SKILL.md#L1-L8), [plugin declaration](https://github.com/Splitwolf1/adlab/blob/59f792a5546c00b0a377ea550e065e9ea26e696e/.claude-plugin/plugin.json#L1-L7).

## Sisazal1: a compact, real extraction CLI

The entire implemented pipeline is `analyze_tiktok.py`: yt-dlp metadata query, download, FFmpeg 16 kHz mono audio, local Whisper CLI, interval frames, RapidOCR, summary and report JSON. The CLI accepts one URL and exports files; there is no web app, subject discovery, bulk scheduler, ranking algorithm, semantic creative analysis, generation client, performance history, or actual audience-retention measurement. [Main pipeline and output](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L239-L327).

Declared Python dependencies are `yt-dlp>=2024.0.0`, `openai-whisper>=20231117`, `rapidocr-onnxruntime>=1.3.0`, and `pillow>=10.0.0`; these are lower bounds rather than reproducible pins. FFmpeg and CLI executables are checked on PATH. Whisper/PyTorch and ONNX transitive model/runtime dependencies are not locked. [Requirements](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/requirements.txt#L1-L4), [tool check](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L255-L258).

Metadata includes identifier, title, creator, duration, views, likes, comments, repost count, upload date/timestamp, track, artist, description, and description-derived hashtags. All values originate from what yt-dlp can return for that specific URL. It neither discovers the most viral videos nor guarantees these fields are available. [Metadata implementation](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L62-L89).

Whisper JSON is preserved with segments. OCR reports frame filenames and recognized text/confidence, discarding bounding boxes. The report maintains a separate approximate frame-time mapping. [Transcription](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L116-L133), [OCR and time mapping](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L149-L188).

The repository includes the full MIT license with copyright notice. Substantial reuse must retain this notice; dependency licenses remain separately relevant. [License](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/LICENSE#L1-L21).

### Implementation defects inferred from source

These are static findings, not failures reproduced against TikTok:

1. **Metadata corruption:** fields are joined with `|`, then only the final output line is split at every pipe. A title/description containing pipes shifts fields; a multiline description may make its last line look like the full record. Numeric conversions can then fail. A JSON metadata record avoids delimiter collisions. [Lines 64–85](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L64-L85).
2. **Default language is Spanish:** the argument defaults to `es`. The help describes `None` as auto-detect, but argparse does not translate the literal string `None` to Python `None`; any nonempty value is passed to Whisper as a language. [Lines 120–123](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L120-L123), [lines 243–245](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L243-L245).
3. **Stale transcript contamination:** transcription ignores process success, then returns the first existing `transcript.json` or `audio.json`. Default runs share one output directory. A failed later transcription may return an earlier video's transcript. Use unique job directories and validate successful output creation. [Lines 116–133](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L116-L133), [output directory](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L260-L266).
4. **Approximate timestamps presented alongside OCR:** OCR `timestamp` is always null; a separate map estimates `i * duration / n`, ignoring actual FFmpeg presentation timestamps. Second-zero formatting also disappears because `if ts` treats zero as false. This is insufficient for precise hook timing. [OCR mapping](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L168-L188), [summary formatting](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L217-L225).
5. **Extraction failure is confused with missing content:** Whisper failure returns `{}`, but the summary labels missing segments as no speech/music only. Missing OCR dependency returns `[]`, later shown as no on-screen text. The report needs independent stage status/errors so absent evidence is not misclassified as a content observation. [Whisper failure](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L125-L133), [OCR import failure](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L149-L157), [summary](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L205-L227).
6. **Batch/job safety is absent:** subprocesses have no timeout, frame interval has no positive-range validation, the common video/audio/report names are overwritten, and there is no durable queue or idempotent cache. These choices are workable for a manual prototype but must change before parallel 100-video jobs. [Subprocess helper](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L27-L30), [FFmpeg extraction](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L136-L146), [arguments and report file](https://github.com/Sisazal1/tiktok-video-analyzer/blob/484ae10d508e902354bd2acd971b0c0839480bcb/analyze_tiktok.py#L239-L266).

## Recommendations for TIKYTOKY

Build an original application around replaceable adapters instead of trying to run the five repositories as one process:

- Accept any subject, audience, language, country, date window, and brand brief. Discovery adapters return evidence with source, observation time, video URL/ID, and nullable metrics. Show coverage and ranking basis; sampled search results cannot establish a complete census of all viral videos.
- Keep manual URL/import paths usable when search credentials or platform access are unavailable. Return clear provider failures rather than fabricated videos or metrics.
- Normalize metrics and rank within the selected subject/window. Display raw views, engagement per view, age-adjusted velocity where available, and creator-relative outlier only when a sufficient observed baseline exists. Retain source data so every score can be inspected.
- Use local yt-dlp/FFmpeg/Whisper/OCR as optional extraction workers. Each job gets a unique directory, bounded duration/file size, real timestamps, explicit stage states, and reusable artifacts. A transcript-only sample must be labeled as such.
- Apply an original evidence-based creative rubric to each video, then aggregate supported patterns across the cohort. Cite sample IDs, timestamps, sample count, and exceptions. Association in selected winners is a hypothesis, not proof of causality.
- Generate original spoken scripts plus on-screen text, shot plan, timing, CTA, and hook variants from the cohort patterns and the user's actual offering. Distinguish a real model response from a deterministic offline template. Prevent unsupported product claims and excessive copying of source dialogue.
- Store published-video snapshots and experiments separately from modeled attention risk. Actual views/likes/shares can validate outcomes; estimated attention timelines are never actual creator retention curves.

Most valuable pieces to learn from these two projects: AdLab's dense hook inspection and transferable-recipe structure; Sisazal's small local extraction pipeline. Neither supplies the user's requested subject-wide discovery, evidence aggregation, original script generation, and closed-loop measurement as a finished system.
