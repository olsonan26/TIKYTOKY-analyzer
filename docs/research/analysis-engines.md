## Mharis-code/videoanalyzer

### Actual data flow

`scripts/watch.py` is a CLI orchestrator: URL/local path -> `download.py` -> ffprobe/FFmpeg sampled JPEG frames -> native VTT captions -> optional cloud Whisper -> stdout markdown containing media metadata, paths and transcript. It does not itself call a vision/analysis LLM. The upstream README explicitly describes a separate Claude Code vision step consuming frame images and writing the creative report. This is a useful preprocessing toolkit plus an agent workflow, rather than a standalone viral research service. Sources: [watch entry point and imports](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/watch.py#L1-L22), [pipeline description](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/README.md#L39-L70).

Implemented components:

- yt-dlp fetch at up to 720p, no playlists, English native/automatic VTT subtitles and basic title/uploader/duration metadata. It does not expose engagement counters from the info JSON, perform keyword search, rank videos, or accumulate a research corpus. [Download and metadata mapping](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/download.py#L62-L117).
- Duration-based frame budget capped at 2 fps; defaults in `watch.py` are 80 frames and 512px width, with a hard 100-frame cap. Focus ranges and timestamped frame paths exist. [Sampling budget](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/frames.py#L94-L131), [CLI arguments](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/watch.py#L25-L56).
- VTT parsing, consecutive duplicate cue merging, time filtering and readable transcript formatting. [Transcript parser](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/transcribe.py#L24-L87).
- Optional Groq/OpenAI Whisper API transcription, with key selection and retries. No local ASR/model dependency is shipped. [Providers and key resolution](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/whisper.py#L25-L83), [provider requests](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/whisper.py#L264-L300).

### Limits and implementation issues

- Hook/story/CTA/replication are qualitative agent output, not a trained virality predictor or validated retention measurement. No dataset, benchmark, measured audience curve or prediction evaluation is shipped.
- Frame sampling is useful for scene summaries but cannot reliably resolve every half-second edit, spoken delivery or fine optical flow. Long videos become sparse; upstream itself documents the limitation. [Sampling limit](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/frames.py#L18-L24), [long-video warning](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/watch.py#L176-L184).
- Reusing `--out-dir` can mix stale outputs: download selects the first `video*` media file that exists and treats that as success even when the current download returns an error. Frame extraction also enumerates all existing `frame_*.jpg` files. New per-job directories or explicit clean output are needed in a service. [Download presence check](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/download.py#L44-L59), [download result handling](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/download.py#L87-L94), [frame enumeration](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/frames.py#L172-L184).
- Subprocess calls in download/frame extraction have no timeout. The CLI creates persistent temporary work directories and asks for manual deletion. A batch service needs bounded processes, quotas, cleanup and durable job state. [download subprocess](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/download.py#L87-L94), [working directory](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/scripts/watch.py#L54-L61).
- Python, yt-dlp, FFmpeg and ffprobe are external dependencies. Running installation changes global tool/Claude skill setup; the new app should have its own explicit local setup. [Dependency list](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/README.md#L76-L85), [installer effects](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/README.md#L97-L105).

The MIT notice is explicit: [LICENSE](https://github.com/Mharis-code/videoanalyzer/blob/aa0c88ade21f4a12b47d02f5c757ed8e566dca90/LICENSE#L1-L21). Best integration: reuse/adapt the bounded preprocessing design and report dimensions; if copying code, include the notice and keep provenance. Do not install the upstream agent instructions globally as part of the app.

## Pra1hamCodes/HOOK_ANALYZER (Hook Architect)

### Actual application and data flow

`RGIT/backend/main.py` is the main FastAPI application, with a vanilla HTML/JS frontend. Separate Flask `videoapi/` and Vite `video-pipeline/` folders are prototypes, not the principal product. The upload endpoint validates extension, reads the whole upload into memory, writes a UUID-named file, validates duration, and starts a daemon thread. Source defaults cap videos at 120 seconds and analysis at 5 fps. [Main upload](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L1202-L1273), [processing configuration](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/core/config.py#L25-L41), [documented main/prototype folders](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/README.md#L111-L140).

The analysis performs real signal extraction: FFmpeg audio/frame preprocessing, librosa audio features, OpenCV optical flow/histogram cuts/Haar face detection, optional Ultralytics YOLO, speech recognition/TextBlob, heuristic emotion alignment, weighted signal fusion, hook grading and optional LLM coaching. SQLite stores analyses/profiles/history; WebSocket progress, comparison, editing, report/PDF and reference-video endpoints exist. [Pipeline extraction](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L244-L303), [signal fusion and hook scoring](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L396-L467), [vision implementation](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/visual_analyzer.py#L94-L188).

### ML and retention validity

The retention curve is an uncalibrated simulation. It starts with 100 virtual viewers, applies hard-coded platform decay rates, opening penalties, attention thresholds and optional external flags, then calls the remaining virtual count `retention_pct`. These values are neither actual analytics nor evidence-backed calibrated probabilities. [Explicit simulation and arbitrary platform profiles](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/retention_curve.py#L1-L84), [curve loop](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/retention_curve.py#L133-L214).

`train_models.py` generates synthetic audio/visual features and transcripts (literal repeated `word` tokens), assigns zone labels from fixed thresholds, and creates overall scores from its own weighted feature formula. It trains and reports accuracy/R² on the same training data. That can demonstrate plumbing but does not establish predictive performance on actual people watching actual videos. [Synthetic transcripts and labels](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/train_models.py#L189-L230), [in-sample classifier evaluation](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/train_models.py#L237-L279), [synthetic training entrypoint](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/train_models.py#L507-L549).

Incremental learning also uses the application's own computed zone/overall labels, rather than observed views, completion rate, conversions or actual audience retention. It learns its existing scoring behavior, not demonstrated audience response. [Zone labels come from generated timeline](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/ml_engine.py#L140-L181), [user-weight target is computed overall_score](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L716-L737).

README claims predictions begin after 2 videos and become reliable after 5, but `DropZonePredictor.MIN_SAMPLES` is 20 and there is no held-out measured-outcome validation supporting reliability at either count. [README claim](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/README.md#L46-L47), [20-video code gate](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/ml_engine.py#L81-L84), [gate enforcement](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/ml_engine.py#L119-L135).

### Important integration risks and mismatches

- The nominally local pipeline automatically attempts to upload the complete video and audio to a hard-coded development-tunnel endpoint. The external client disables TLS certificate verification. This contradicts treating it as reliably private/local by default and must not be inherited. [Default remote URL and audio upload](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/external_api.py#L15-L45), [video upload and TLS setting](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/external_api.py#L78-L89), [unconditional pipeline calls](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L324-L345).
- The main transcription module says local/offline in comments but calls Google's internet speech endpoint. Failure becomes an empty transcript. It produces no real word/segment timestamps; another module approximates transcript segments by evenly distributing words over duration. [Actual Google call and empty fallback](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/transcript_analyzer.py#L10-L40), [time approximation](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/multimodal_coach.py#L260-L277).
- Vocal emotion is threshold rules over acoustic energy/pitch; it should be described as an acoustic heuristic. DeepFace is optional and absent from the primary requirements file, so facial emotion may be unavailable even after installing listed dependencies. [Emotion fallback](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/emotion_analyzer.py#L10-L40), [requirements](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/requirements.txt#L1-L22).
- Audio “pacing” is normalized onset strength, not measured spoken words/second; transcript scoring uses word count while assuming a short fixed video, so comparing different lengths is weak. [Audio formula](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/audio_analyzer.py#L107-L127), [transcript density formula](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/transcript_analyzer.py#L56-L67).
- Login/signup is explicitly stub authentication in frontend source; backend endpoints accept profile IDs without authenticated ownership checks in inspected handlers. Do not expose this application publicly as a multi-user service without replacing auth. [Stub auth label](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/frontend/static/auth.js#L1-L4), [upload accepts profile ID](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L1202-L1208).
- Unbounded daemon threads, whole-file upload reads and cached pickle model state are local prototype architecture. They need bounded work queues, input/resource limits and trusted model handling for deployment. [Upload/thread creation](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/main.py#L1218-L1266), [pickle loading](https://github.com/Pra1hamCodes/HOOK_ANALYZER/blob/e03d930b3f19f412be1f02c33dad2d414cd14101/RGIT/backend/services/ml_engine.py#L61-L74).
- The source has no global TikTok/Instagram subject discovery or corpus-level viral ranking. YouTube reference import and static `trends_db.json` song suggestions do not establish that any selected videos are the most viral in a subject. A separate data-source/discovery layer is required.
- The dependency list includes Ultralytics; upstream and dependency/model licensing must be evaluated separately before incorporation. This review does not establish commercial redistribution rights for an unlicensed repository.

## Recommended combined implementation

Build a new application with a consistent evidence model and independently written integration code. Use the MIT tool's extraction approach where appropriate and borrow Hook Architect's general feature concepts (timestamped audio/visual observations, first-three-second rubric, source-linked suggestions), without copying its unlicensed source or unvalidated percentages.

Required boundaries:

1. Discovery returns a bounded, timestamped sample from an identified provider; rank observed counters within that sample and disclose provider/date/query/coverage. Do not claim to have found every video or the globally most viral videos.
2. Preserve each video's URL/creator/published date/observed counters and distinguish unavailable counters from zero. Keep observed performance separate from heuristic quality scores.
3. Extract real timestamped captions/ASR, sampled frames/OCR and audio observations. Label missing tracks and failed providers; never fabricate observations.
4. Compare high-performing examples with weaker examples within similar topic/platform/time windows. Report descriptive patterns with sample counts, not causal proof.
5. Generate an original script tailored to the user's brand, audience and offer. Cite which source patterns informed each section; avoid verbatim copying of creator scripts. Include alternative hooks, shot list, overlays and CTA.
6. Track the user's actual post metrics as dated snapshots, with 24/48-hour deltas only when snapshots support them. Calibration needs outcome data and held-out evaluation before numerical retention predictions can be presented as calibrated.

Runtime validation still needed: actual allowed video downloads, FFmpeg availability, real provider credentials/quotas, extraction accuracy, persisted batch jobs, browser flow and output generation. This static audit alone does not verify any of those live behaviors.
