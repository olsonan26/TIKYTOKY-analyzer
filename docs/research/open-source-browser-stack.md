## Browser Use: intelligent navigation with a bounded evidence role

The repository provides a real Python agent, a browser session, structured Pydantic output, and provider adapters. It can navigate pages and return typed results; it is not a deterministic metric collector or an exhaustive viral index. The primary worker uses Browser Use to find actual source URLs, then closes that controller before a plain Playwright phase reads page titles/public hydration. The model never supplies counters.

The current source has a native `ChatOpenRouter` adapter, including an environment-key fallback, OpenRouter base URL and structured output handling. `ChatOpenAI` also accepts an explicit `base_url`, but a native adapter avoids pretending the provider is OpenAI. The worker uses `ChatOpenRouter(model=OPENROUTER_MODEL, api_key=OPENROUTER_API_KEY)` with retries disabled, a request timeout, bounded output tokens and a bounded agent-step count. Sources: [runtime and dependencies](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/pyproject.toml#L1-L58), [native OpenRouter adapter](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/llm/openrouter/chat.py#L26-L94), [structured OpenRouter completion](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/llm/openrouter/chat.py#L180-L203), [OpenAI-compatible configuration](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/llm/openai/chat.py#L25-L64), [structured output example](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/examples/features/custom_output.py#L21-L47).

The upstream browser API supports a dedicated persistent user-data directory, domain restrictions, download controls and local/cloud selection. Cloud is optional. Some convenience defaults are inappropriate for this task: telemetry defaults on; extensions may be downloaded automatically; the cloud CAPTCHA watchdog defaults on. The worker explicitly chooses a local browser, disables extensions and CAPTCHA solving, disables cloud sync/telemetry by default before lazy import, and offers only read/navigation tools to the agent. It does not supply passwords to the model, add stealth patches, rotate proxies, solve challenges, comment, follow or publish. Sources: [browser constructor options](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/browser/session.py#L208-L267), [extension and solver defaults](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/browser/profile.py#L648-L654), [telemetry/cloud-sync environment behavior](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/config.py#L54-L63), [tool filtering](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/tools/service.py#L441-L455), [run step limit](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/browser_use/agent/service.py#L2521-L2527).

License: [Browser Use MIT notice](https://github.com/browser-use/browser-use/blob/aa093a843da5edbf323c0b4145c9b6a0db3ecde8/LICENSE#L1-L21). Optional cloud browser service terms, browser binaries, LLM service terms and package dependencies are separate from the source-code license.

## Playwright MCP: optional alternate controller, not a second owner

Playwright MCP is an MCP tool server intended for an MCP-capable host. It is not required inside the Python Browser Use loop. Its source package pins Playwright/Playwright Core 1.64 alpha and requires Node >=18; the worker's Python Playwright environment is independent. Sources: [package/runtime/dependencies](https://github.com/microsoft/playwright-mcp/blob/ab6d67cbf8b619338f096980806fdbe29432cc4d/package.json#L1-L56), [Apache license](https://github.com/microsoft/playwright-mcp/blob/ab6d67cbf8b619338f096980806fdbe29432cc4d/LICENSE#L1-L25).

The upstream documentation explicitly says a persistent profile can only be used by one browser instance at a time. Its `--user-data-dir`, `--isolated`, `--storage-state` and CDP options offer several session modes. Our integration uses one dedicated local profile (`worker/.data/browser`) for the primary controller or manual login, and a shared fail-fast owner lease (`worker/.data/browser-owner.lock`). An MCP launcher must acquire that same lease and release it after shutdown. It must never attach concurrently while Browser Use or plain Playwright owns the profile. A separate isolated profile is required for concurrent diagnostic work. Sources: [profile options](https://github.com/microsoft/playwright-mcp/blob/ab6d67cbf8b619338f096980806fdbe29432cc4d/README.md#L435-L457), [persistent profile and ownership warning](https://github.com/microsoft/playwright-mcp/blob/ab6d67cbf8b619338f096980806fdbe29432cc4d/README.md#L462-L485).

The MCP server binds to localhost by default. Its allowed-origin option explicitly is not a security boundary. Do not expose an unauthenticated browser-control server to the internet. It remains an optional local inspection alternative, not the Vercel dashboard's browser runtime. [Network options and limits](https://github.com/microsoft/playwright-mcp/blob/ab6d67cbf8b619338f096980806fdbe29432cc4d/README.md#L409-L430).

## TikTok-Api: optional actual secondary metadata calls

TikTok-Api is explicitly an unofficial wrapper, not TikTok's official Display API. It provides its own Playwright sessions and raw video dictionaries with `statsV2`/`stats`. The runtime/API dependency requirements are visible in setup source. [Package description, version and dependencies](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/setup.py#L8-L43), [raw video fields](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/api/video.py#L230-L247), [MIT license](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/LICENSE#L1-L21).

Important source findings:

- Default session creation applies a stealth helper. A supplied `page_factory` takes a different branch and skips that helper. The library itself still performs small mouse movements and ordinary session setup. We do not add patches, impersonation scripts, proxy rotation, challenge solvers or replayed tokens. [Page-factory/default branch](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/tiktok.py#L338-L394).
- Custom browser-context and page factories are real supported arguments. The worker opens a distinct persistent `.data/tiktok-api` context with its own lease, uses one session and disables automatic session recovery. It never shares the primary Browser Use/CDP context or exports browser cookies into the dashboard. [Factory/session arguments](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/tiktok.py#L436-L458), [factory browser creation](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/tiktok.py#L520-L545).
- Keyword-video search is not a straightforward stable `api.search.videos()` convenience method in this pinned source. `Search.search_type` documents only user search as supported without additional auth, while an example directly calls a video-search endpoint. Treat video search reliability as unverified rather than advertising a guaranteed API. [Search implementation and limitations](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/api/search.py#L45-L116), [keyword example](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/examples/video_keyword_search_example.py#L8-L43).
- The wrapper's `make_request` uses the owned live browser session and the wrapper's own request-signing machinery. The application does not reverse or modify signing or attempt to defeat a server challenge. We call at most once per item with retries=1. Denied, empty, challenged or failed responses stop secondary enrichment and preserve previously observed evidence. [Actual request method](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/tiktok.py#L815-L901).
- The wrapper's `video.info()` contains synchronous `requests.get` without a timeout; this is unsuitable for directly blocking the worker event loop. Its hydration parser supports `SIGI_STATE` and `__UNIVERSAL_DATA_FOR_REHYDRATION__`. The plain Playwright fallback reads those public-page structures and is labeled **public page hydration**, never mislabeled as an API call. [HTTP/parser implementation](https://github.com/davidteather/TikTok-Api/blob/99630590a2e24997f69822b0541f396424f44d40/TikTokApi/api/video.py#L78-L178).

`TIKTOK_API_ENABLED=true` explicitly opts into the actual secondary library calls. Without it, the adapter returns an explicit disabled warning rather than pretending enrichment occurred. Missing dependencies, login gates, CAPTCHA, rate limiting and regional availability remain real constraints. Resolve login manually in a profile owner session; do not automate challenge solving. No competitor retention curves or comprehensive global ranking are available from these fields.

## Implemented adapter contracts and verification limits

- `BrowserAgent.discover(subject, limit, period_days, platform='tiktok', creators=None, hashtags=None, creative_center=True)`, `collect_urls(urls)` and `close()`; also `discover(request, emit)` wrapper. Requested creator/hashtag pages and Creative Center are task inputs; follow-up exploration is capped at three additional creators. A deterministic per-step DOM hook records actual visible anchor targets, and proposed model URLs are accepted only if those targets were independently observed. Results contain `videos`, `warnings`, `blocked`, `manualLoginRequired`, `sources`, visited page URLs and, where collected, `coverage`.
- `TikTokMetadataAdapter.collect_public(urls)` / `enrich_videos(videos, emit)` performs the optional real library request path. Stateless `normalize_tiktok`/`hydration_videos` parse observed data, preserve signed media queries and leave absent counters unknown.
- Unknown publication dates remain candidate evidence with an explicit unverified-window warning; downstream metadata extraction must verify dates before presenting a filtered date cohort.
- Profile lease, canonical URL checks, missing-counter handling, public hydration normalization, date-window validation, disabled-secondary behavior, the real library method contract and independent browser-link evidence filtering passed eight local Python tests. The contract tests replace browser/provider classes with fakes; they made no network or model calls.

## Actual local runtime check: 2026-10-20

Chromium and the matching headless shell were installed with this worker's Playwright interpreter. An actual Browser Use run researched the public TikTok search for `astrology`, bounded to six steps and three results. It stopped with `blocked=true` and `manualLoginRequired=true`, returning **zero videos**. This verifies launching the installed browser/agent path and safe stopping, not successful TikTok discovery. No login or access challenge was bypassed. See [sanitized primary probe](browser-public-smoke.json).

An actual optional TikTok-Api probe used the public example URL from the pinned upstream `video.info()` documentation. Custom plain browser/context setup succeeded far enough to issue the public item-detail request; that request raised `EmptyResponseException`. **Zero new metric observations** were accepted, existing evidence stayed intact, and no retry or bypass was attempted. This is a provider/access failure, not successful enrichment. See [sanitized secondary probe](tiktok-api-public-smoke.json). Primary/secondary profile leases were released after the checks.

Two installed-version compatibility details were handled in our adapters, without modifying upstream source: Browser Use configuration is directed into ignored `worker/.data/browser-use-config` before import; and Browser Use 0.13.11 internally forces DeepSeek navigation to DOM-only mode. The adapter now requests DOM-only navigation explicitly for DeepSeek. This restriction belongs to that Browser Use version, not the OpenRouter model's separately verified multimodal capabilities. The media interpretation pipeline sends decoded frames directly to the vision-capable OpenRouter API.

Successful authenticated platform collection still requires an owner-supplied valid local session and another observed run. Browser Use/manual login/MCP must remain sequential owners of the primary profile; the TikTok-Api profile has its own independent login state.

Credentials remain in environment variables or local ignored browser profiles. Persistent profile cookies are sensitive local state and must not be committed, backed up into public artifacts or returned by worker API responses. Vercel serves the dashboard; long-running browser execution belongs to the Windows/WSL2 worker.
